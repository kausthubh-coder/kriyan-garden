# Brief 06: Android app with Expo, plus server-sent reminders

Read `AGENTS.md`, `docs/PLAN.md` section 11, the prototype's phone layout (`docs/design/proposals/prototype/app.css` under `@media (max-width: 820px)` and `phone.html`), the web components in `apps/web/src/components/app/` for behaviour, and `packages/core` for the parser and tokens. Use the installed Codex plugins for building and testing React Native apps and for testing Android apps where they help.

## Setup

- `apps/mobile` with Expo SDK 57 (React Native 0.86, React 19.2.3, already pinned at the root), Expo Router, TypeScript strict. Android only: no `ios` folder, no Apple sign-in, no iOS-specific config. Package name `app.kriyan.android`.
- Follow the Expo monorepo guide for Bun workspaces. Metro must resolve `@kriyan/core` and `@kriyan/backend` from the workspace. Run `npx expo install --check` and fix every mismatch. Add an `expo-doctor` step to CI for the mobile workspace.
- Auth: `@clerk/expo` with `tokenCache` from `@clerk/expo/token-cache` and `expo-secure-store`. Sign in with email and password and Google (`@clerk/expo-google-signin`; needs a development build, not Expo Go). Env `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`, `EXPO_PUBLIC_CONVEX_URL`.
- Data: `ConvexProviderWithClerk` from `convex/react-clerk`, the same public functions as the web app.
- Fonts: Schibsted Grotesk static weight files 400, 500, 600, 700 via `expo-font`. Tokens from `packages/core/src/tokens.ts` converted to React Native values in `apps/mobile/src/theme.ts` (generated by the same tokens script; no hand copies).
- EAS: `eas.json` with a `preview` profile that produces an installable APK (`buildType: "apk"`) and a `production` profile that also produces an APK. The owner will run `eas login`; do not store credentials. Document the build command in `docs/site/android.md`.

## Screens (bottom tabs: Day, List, add button, Week, Goals)

Port the prototype's phone layout:

- **Day**: header with day name, date, previous/next/today; summary line; area filter chips; "Any time today" cards; the timeline with the same block styles (solid for tasks with a length, outlined marker for tasks without, grey for classes, faded for done); now line on today. Long-press a block or tray card to drag it on the timeline with haptic feedback on pick-up and drop; snap to 15 minutes; resize handle appears while a block is selected. Tap opens the task sheet.
- **List**: grouped by area with "No date yet"; swipe right on a row to complete (haptic), swipe left to open the schedule sheet (Today, Tomorrow, pick a day, any time).
- **Week**: seven-day strip with load bars, then the selected day's list; deadlines below.
- **Goals**: goal cards with pace bar and milestones; tap for the goal screen.
- **Add** (centre button and a long-press shortcut on the app icon via `expo-quick-actions` if it supports Android): the quick-add bottom sheet with live chips from `@kriyan/core`. Also register as a share target so shared text opens the sheet pre-filled (`expo-share-intent` or the current Expo-recommended package; if none is stable, skip and say so).
- **Task sheet**: the same fields as the web panel: area, project, day, time, length (optional), deadline, goal, repeat, reminders, notes, delete with undo.
- **Settings**: areas, projects, classes, capacity, day hours, notifications toggle, sign out, delete account (calls `profiles.resetAll` and then Clerk's user deletion).
- **Onboarding**: the same five steps as the web, as a paged flow.
- Offline: Convex's client reconnects on its own; show a small "Offline, changes will sync" line when disconnected.

Every screen has loading, empty and error states. Touch targets at least 44dp. Respect the system reduce-motion setting.

## Reminders (server-sent)

Backend, in `packages/backend`:

- Add `pushTokens` (ownerId, token, platform, updatedAt) and `reminderJobs` (ownerId, taskId, fireAt, scheduledId, state) tables.
- Install `@convex-dev/expo-push-notifications` and register it in `convex.config.ts`.
- When a task is created or updated with a `date` and at least one reminder, compute each reminder's fire time in the profile timezone (`at_start` and `before` need a `time`; `morning_of` is 09:00; `day_before` is 18:00 the previous day; `at_time` is the given time), cancel any existing jobs for the task, and schedule one internal action per future reminder with `ctx.scheduler.runAt`. Store the scheduled ids. Completing, deleting, or removing the date cancels the jobs. Rescheduling a repeating task's next occurrence schedules its reminders.
- The internal action sends a push to every token of the owner with the task title and time, and marks the job sent. Log failures; never throw to the scheduler.
- Tests with `convex-test` for scheduling, cancellation on move and complete, timezone handling across a DST change, and the `before` reminder in the past not being scheduled.

App:

- Ask for notification permission on first launch after onboarding, with one sentence on why. Register the Expo push token with `pushTokens.register` on sign-in and whenever it changes. Tapping a notification opens the task.
- Android notification channel "Reminders" with default importance and no custom sound.

## Release

- `scripts/release-android.ps1` and `.sh`: bump the version in `app.json`, run `eas build --platform android --profile production --non-interactive`, download the APK, and create a GitHub release `android-v<version>` with the APK attached using `gh release create`. Do not run the release; describe how in `docs/site/android.md` and make `/download` on the web point at `https://github.com/kausthubh-coder/kriyan-garden/releases/latest`.
